# Up to three miners (2026-10-26)

User request: up to 3 miners to rescue per level, a counter in the HUD, the level
ends only once all are rescued. Answers: purple squares right aligned on the
bombs row; squares (lives and bombs) half as far apart; ramp 1/2/3 miners at
levels 1-6 / 7-13 / 14-20; a rescue that is not the last gives a blip + 500.

## Runtime (ROM)
* The level's own miner is unchanged (LevelDataTable +0/+1, miner slot). **Extra
  miners are enemy records of type 15** (`MINER2`): drawn through the ordinary
  object path with the MINER art (`ObjSpriteOffTable[15] = OBJ_MINER`, window 16),
  standing at y = 99 px (canvas row 11, stage y 8.25) like the own miner.
  Every `and #7` consumer folds 15 to 7 (RAFT): bomb blast skips it, laser tip and
  laser body skip every type >= 6 (`cmp #KEY / bcs`), CheckEnemyHit routes 14/15 to
  `CEH_KeyDisp`.
* **LevelStartRoom b6-4 = miners still to rescue** (b4 = the own miner, b5/b6 =
  the extras by room parity `RoomNo & 1`). `LoadLevelB2` seeds `$10 | (byte & $60)`
  from level byte +0 (b6-5 = the extras' parity mask, b4-0 = the miner room, b7 =
  facing); `LevelMinerRoom` is stored as `byte & $9F`. Cells use b3-0, the key b7.
* Rescue: the own miner -> `RescuePrimary` (clears b4; if others remain it
  vanishes = `LevelMinerRoom := $FF`); an extra -> `CEHMiner` (dead bit + clears
  its bit). Both end in `MinerRescued`: bits left -> `MinerMore` (blip on ch0 +
  500 points = 10 x AddScore $50), none left -> `TallyTramp` (the usual tally).
  A rescued extra stays gone on re-entry (`EBLCellCheck`: bit CLEAR = rescued).
* Code placement (bank0 is full): `CEHDispatch`/`RescuePrimary` in the `$F97A`
  hole, `CEH_KeyDisp` + cell arm in `$FBA2`, `CEHMiner` + bit tables in `$FDDE`,
  `MinerMore` before the `$FFE6` pin. bank2: `EBLCellCheck` before `$FE96`, the
  slot-1 tables (now 16 entries) and the bit tables in the `$FC29` / `$FBFC` holes.

## HUD (bank1)
Lives, bombs and miners are QUAD-size players: one GRP bit = 4 px, so squares on
every other bit sit 8 px apart (the old NUSIZ copies were 16 px). `SquarePat`
(lives 0-3, bombs 0-5) and `MinerPat` (mask -> squares packed to the right end of
P1 at X 126, purple `$54`). The 5th bomb is missile 0 (`NUSIZ0 = $27`, X 49). The
bombs row costs one more WSYNC (3 positioning lines); `HudPad` 8 -> 7. Its
patterns are computed in the blank gap line above (a positioning call that
returns after cycle ~66 plus setup would put the next WSYNC on the next line:
that was +2 lines/frame while developing). Guard: `tools/test_hud_squares.py`.

## Tooling
* Editor: brush `J. Extra miner` (`EnemyType::EXTRA_MINER = 15`, label `M2`), the
  level's own miner is still the SET_MINER_GOAL brush.
* `convert_level`: type 15 allowed; `extra_miner_mask()` (<= 2 extras, rooms of
  different parity, miner room < 32); per-room seat rule (cells he covers are
  air, the cell under his feet solid, standing on the bottom row of band 0/1/2 (canvas row 3/7/11, y 2.25/5.25/8.25; the generator uses band 2), one per room, never
  in the own miner's room or a door room).
* Generator (`PlaceExtraMiners`, before the power cells): ramp above; rooms
  spread along the route (1/3, 2/3 of the visiting order); a host room has a
  cell run with air at band 2 and a solid cell under it, reachable without a
  bomb or spider, and gives up one plain enemy when full. Levels that cannot
  find two hosts get one (level 18 of the current stage). `AnalyseReach` now
  returns `reach` (cost-0 cells) and its time route visits every extra miner
  first, so the power-cell plan covers the detours.
* Guards: `tools/test_miners.py` (frozen ROM: seed, own/extra rescue, last-one
  tally, re-entry, laser/bomb immunity), `test_generator` (ramp, parity, hosts),
  `stage_reach` (`reach_cells`, `route_segments` with waypoints), `brushtest`.

## Seat maths: the VISIBLE edge is 4 * column (fix 2026-10-26)
`enemy_x_px` returns the REQUESTED sprite X (4*col + 4/7) that pins the TIA coarse
position; the sprite is drawn with its left edge on 4*col. The first seat check
used the requested X, so a miner on display column 36 was "inside a wall" (cell
18 -> 19 -> model cell 0) when he really covers px 144-151 (model cell 1, air).
The converter, the generator (`spotIn`, the route's waypoint) and
`stage_reach.extra_miner_nodes` now use `4 * col`.

## Facing, flicker and clipped feet (2026-10-26)
* **Facing** (restored per slot, 2026-10-26): the art is stored facing RIGHT; a
  miner that faces left gets the hardware mirror (REFP1 D3). REFP1 is ONE register
  for GRP1 and a frame can draw TWO objects, so each slot gets its own value:
  slot 0's is written by bank2 `S1Fin` (every `StageSlot1B2` exit; TIA writes work
  from any bank), slot 1's is left in `ObjRefs` ($89 b2) and written by
  `Slot1Hook` at the band swap - before its aligning WSYNC, where the hook has
  ~30c of slack (measured gap 162 of 228c). `MinerRef` decides: the level's own
  miner follows `LevelMinerRoom` b7 (= faces right, so clear = mirror), an extra
  miner follows its record b7 (= left). Only OBJ_MINER ever mirrors. The bank1 HUD
  already clears REFP1 first. `verify_build` now allows exactly one `sta REFP1` in
  bank0, inside the hook. Existing stages whose `miner_dir` is -1 (the editor
  default) now show the miner facing LEFT. Guard: `tools/test_miner_facing.py`.
* **Flicker** (`PinSlot0`, bank2): with two objects in different bands slot 1 holds
  the higher one and slot 0 is pinned to the other. The pin value is
  desired + count - 1, but the guard `cmp #2 / bcs` ("3+ candidates") tested that
  VALUE, so it refused desired = 1: a higher-band object listed FIRST (power cell
  before the miner) left the lower one to the 1-of-2 rotation. The guard now
  tests the candidate count. Guard: `test_slot1_pair.py` case 1b.
* **Feet** (revised): an extra miner stands with his feet EXACTLY on the ground:
  12 visible rows end on the band's last line, top = band edge - 12 px = 24 / 60 /
  96 px (stage y 2 / 5 / 8). The editor brush snaps to those (a click anywhere in
  a band, the floor band uses band 2); the converter accepts +-3 px for older
  data. (The first version put his top 9 px above the edge, so 3 px of feet sank
  into the next band and an object there cut them off; that rule is gone.)
