# Unified stage file (`stage.json`) — E1, 2026-10-20

One JSON can now carry the whole project: the shared model shapes AND every
level. This is storage plumbing only — the ROM format, the room/model payloads
and the generated bytes are unchanged, and the live per-level tree keeps working.

## 1. Schema

Canonical on-disk form (what the editor and `--stage` write):

```json
{
  "stage": {
    "models": [ { "id": 0, "name": "Model 1", "width": 10, "height": 3,
                  "tiles": [ ... ] }, ... ],
    "levels": [ { "level_id": 1, "name": "Level 1", "wall_r": ...,
                  "rooms": [ ... ], ... }, ... ]
  }
}
```

* `models` — exactly the array of `rooms/models/models.json`'s `models_file.models`
  (same `ModelData` records, same optional keys).
* `levels` — each entry is EXACTLY a legacy `level_00N.json`'s `level` payload
  (rooms, palettes, miner, rooms' `asym_patches`/`feature_cells`, optional keys).
* `levels` order IS the play order = `LevelDataTable` order. The level NUMBER is
  the ordinal (1-based), not `level_id`: this project's files all carry
  `level_id: 1` (legacy numbering came from the file name) and two stage levels
  may legitimately share an id.
* The bare form `{"models": [...], "levels": [...]}` (no `stage` wrapper) is
  accepted on load by both the converter and the editor; saving always writes
  the canonical wrapped form. A level object wrapped as `{"level": {...}}` is
  also unwrapped on load (cereal's per-level file form).

## 2. Converter (`tools/convert_level.py`)

```
convert_level.py --stage STAGE.json OUTDIR [ROOMS_DIR]
```

Emits the same files the legacy invocation emits for the same content: per-room
`.txt` mirrors (`ROOMS_DIR`, default = the stage file's folder), per-level
`level_00N_rooms.asm` / `level_00N_rooms_data.asm` / `level_00N_blocks.asm`, and
the shared index files (`levels.asm`, `levels_index.asm`, `levels_data.asm`,
`levels_equ.asm`, `models_data.asm`, `spill_*.asm`). Models come from the
stage's own `models` list — never from `models/models.json`.

Legacy CLI paths are unchanged: `convert_level.py LEVEL.json OUT_PREFIX
[ROOMS_DIR]` and `convert_level.py --levels INDEX.asm LEVEL.json...`.

## 3. Build precedence (`src/build.sh`)

1. `$STAGE_FILE` (env override) — build any stage file without touching
   `src/rooms` (the demo/generator hook).
2. `src/rooms/stage.json` — automatic when present.
3. Legacy `src/rooms/level_[0-9][0-9][0-9].json` + `rooms/models/models.json`
   (today's tree — default behaviour unchanged).

`build.sh` prints `Level source: ...`. In stage mode the `.txt` room mirrors are
written next to the stage file (the live `rooms/` tree is the user's and is only
used when its own `stage.json` is the source).

## 4. Editor (`src/tools/editor`)

* `File > Open Stage...` — loads models + levels, switches the stage combo to
  the stage's LEVELS (one entry per level).
* `File > Save Stage` — writes the ONE stage file (creates `stage.json` via a
  Save dialog when no stage is open).
* `File > Convert Project to Single Stage File...` — reads the game-data dir's
  `level_*.json` + `models/models.json` and writes a NEW file the user picks.
  It never deletes, moves or overwrites the legacy files.
* Legacy `Open Level... / Save Level / Save Level As...` keeps working exactly
  as before: opening a `level_001.json` edits and saves that file, no forced
  migration. `SaveModels()` writes `models.json` in legacy mode and the stage
  file in stage mode (so a stage project never touches `models.json`).
* `DataSerializer::SaveStageToFile / LoadStageFromFile` are the plumbing;
  switching the game-data directory leaves stage mode.

## 5. Tests

* `tools/test_stage_json.py` — builds a stage from the FROZEN `src/tests/rooms`,
  runs legacy and stage conversion into two `generated/` dirs and byte-compares
  every emitted file (and the room `.txt` mirrors); repeats with the bare form;
  also compares the stage output with the frozen `src/tests/generated/` baseline.
* `test_editor_roundtrip.py` (`savior_editor --selftest`) — adds a stage
  save→load→save byte round-trip, per-level save equality against the legacy
  frozen levels, and bare-form loading.

## 7. Generator hook (later chunk)

The 20-level generator will emit this one file (canonical wrapped form, levels
in play order) into a path outside `src/rooms`; building its demo is just
`STAGE_FILE=/path/stage.json ./build.sh`. Nothing in the converter needs to
change for it: shared model shapes are already deduplicated by model id and the
row-pool dictionary is global.
