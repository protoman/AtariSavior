# S.A.V.I.O.R.

**A cave-rescue game for the Atari 2600.** Strap on the jet pack, point the helmet laser and
bring every miner home.

*Eorley Savior founded the S.A.V.I.O.R. company (Strategic Aerial Vehicle Infiltration
Operations Rescue) to save people trapped in the deep mines of Minas Gerais, Brazil. You are
Eorley, and the clock is running.*

A from-scratch 6502 assembly game in the spirit of Activision's *H.E.R.O.* (1984): a 32 KiB
F4-bankswitched cartridge (8 banks of 4 KiB), a mirrored-playfield cave kernel, and 32 levels
(484 rooms) produced by the project's own stage generator.

Current release: **1.2.0** (see `src/CHANGELOG.md`).

## The game

- Fly room to room with the jet pack, find the trapped miners and touch them before the power
  bar runs dry.
- Shoot creatures (spiders, bats, snakes, tentacles, giant moths) with the helmet laser, blow
  open thin walls with bombs, grab power cells to refill the timer.
- Mind the hazards: hot rock, blinking phase walls, crushers, locked doors and keys, lamps that
  plunge a room into darkness, and flooded rooms that only a ferry raft can cross.
- Three lives, five bombs per level, an extra life every 50,000 points.
- NTSC, PAL60 and PAL builds. A SaveKey / AtariVox in the right controller jack saves the high
  score and the level you stopped on.

| Control | Action |
|---|---|
| Stick UP | Jet pack |
| Stick LEFT / RIGHT | Fly sideways (the laser fires the way you face) |
| Stick DOWN | Drop a bomb (on the ground) |
| Red button | Fire the laser |
| SELECT / RESET | Pick the level / start the game (title screen) |

The full instruction manual is `src/docs/manual/savior_manual.pdf` (generated by
`src/docs/manual/build_manual.py`).

## Repository layout

Everything lives in `src/`, which is the project root: run all commands from there.

| Path | What it is |
|---|---|
| `src/bank0.asm` ... `bank7.asm` | the eight 4 KiB banks (bank 6, the cave kernel, is generated by `tools/cave_kernel_gen.py`) |
| `src/build.sh` | the build: stage conversion, assembly, padding, verification, sims |
| `src/rooms/` | the stage: `stage.json` (all models and levels) and `models/` |
| `src/generated/` | assembler data converted from the stage (build output; levels 1-4 tracked) |
| `src/tools/` | converters, the headless simulators, the test battery (`test_*.py`), the playthrough bot, `release.py` |
| `src/tools/editor/` | the Qt6 room/level editor and the stage generator |
| `src/tests/` | frozen, test-owned copies of rooms and ROM banks (tests never read the live stage) |
| `src/docs/` | design notes; `docs/agents/` is the architecture reference, `docs/manual/` the manual |
| `src/AGENTS.md` | architecture and project rules (read it before touching the kernel) |

The ROM bank plan is in `src/docs/agents/banks.md`: code first, then room models, then levels,
and a boot stub in every bank (real hardware powers up in an undefined bank).

## Building

### Requirements

- [`dasm`](https://github.com/dasm-assembler/dasm) (6502 cross-assembler)
- Python 3.10+ with `Pillow` and `reportlab` (manual only)
- `py65` for the headless simulations (`pip install py65`). `build.sh` looks for it in the
  interpreter named by `SIM_PY`; set `SIM_PY=$(which python3)` if the default
  (`/home/iuri/python3/bin/python3`) does not exist on your machine. Without py65 the sims are
  skipped with a warning.
- [Stella](https://stella-emu.github.io/) to run the ROM
- CMake 3.20+, a C++20 compiler and Qt6 (Widgets), only for the editor/generator

### The ROM

```bash
cd src
./build.sh               # NTSC -> savior.bin (32 KiB)
TV=pal60 ./build.sh      # PAL60: 60 Hz, PAL colours
TV=pal ./build.sh        # PAL: 312 lines, 50 Hz
FULL_SIMS=1 ./build.sh   # also runs the slow frame-budget simulation
stella savior.bin
```

`build.sh` converts `rooms/stage.json` to assembler data, assembles the banks in dependency
order, pads each to 4 KiB, runs `tools/verify_build.py` and the bomb-fuse sim, and concatenates
the ROM. `STAGE_FILE=path.json ./build.sh` builds another stage without touching `rooms/`.
`tools/build_variant.sh pal|pal60` builds a PAL variant in a scratch copy so the live tree
stays NTSC.

### The editor and the stage generator

```bash
cd src/tools/editor
cmake -S . -B build && cmake --build build
./build/savior_editor                                  # the editor
./build/savior_editor --generate-stage ../../rooms/stage.json   # headless generator
```

The saved stage is generator output: design rules belong in the generator
(`tools/editor/src/DataSerializer.cpp`) and the test that pins them
(`tools/test_generator.py`), not in hand-edited rooms. Rebuild the editor after changing the
generator, because `test_generator.py` does not.

## Testing

```bash
cd src
python3 tools/test_generator.py           # one test
for t in tools/test_*.py; do python3 "$t" || echo "FAIL $t"; done    # the whole battery (94 tests)
python3 tools/test_frame_stability.py --all    # frame length / VBL window in the heaviest rooms
python3 tools/playbot.py                  # a joystick-only bot plays every level on the real ROM
```

Tests boot frozen copies under `src/tests/`, not the live stage, so editing rooms never breaks
them (the few exceptions are documented in `src/docs/agents/testing_and_build.md`).
`tools/playbot.py` flies the live stage and must finish every level; `tools/stage_reach.py`
checks that every level is finishable.

## Cutting a release

```bash
cd src
tools/release.py [--skip-playbot] [--tag]
```

The version comes from `src/VERSION`, and `CHANGELOG.md` needs a section for it. The script
checks for a clean tree, builds with all sims, runs the whole battery, frame-stability and
frame-budget checks, `stage_reach`, the playbot on every level, then builds the PAL60 and PAL
ROMs and the manual. Artifacts and a `RELEASE.txt` go to `src/releases/` (git-ignored); `--tag`
adds the local annotated tag `v<version>`.
